# Database migrations (apply in order, then `supabase/seed.sql`)

| # | File | What it adds |
|---|---|---|
| 0001 | core_schema | scholars, translations, disciplines, works, contributions, sources, claim_sources, editorial_reviews; RLS (public reads published only); publish gate trigger |
| 0002 | hardening | name normalisation, indexes, anon write revokes, insert-only reviews |
| 0003 | security_review | explicit published check on `sources`; `created_by`; publication gate |
| 0004 | publication_integrity | `content_rev`/`last_edited_by`; any substantive change demotes a published scholar; `private` schema, locked-down SECURITY DEFINER functions |
| 0005 | final_hardening | reviews must state the revision reviewed; reviews survive scholar deletion (`ON DELETE RESTRICT`); source-removal guard takes a row lock |
| 0006 | contribution_layer | contribution class, confidence, evidence tiers; invention/discovery gate; two new labels |
| 0007 | timeline_events | uncertain-date events with sources; wired into gate, guards, change tracking, RLS |
| 0008 | scholar_relationships | relationships (member_of, teacher_of, ...) and group scholars (Banu Musa); same source gate; public only when BOTH scholars are published |
| 0009 | admin_rbac_audit_media | admin role; archive state; append-only audit log; media records + private storage bucket + policies; no-op update fix; Arabic yeh normalisation; period_rank; `jit=off` for API roles |

Draft content (never public until it passes the gate) lives in `supabase/content/` and is generated by `tools/build_content.py` and `tools/build_batch.py`.
Tests: `npm run test:sql`, `test:content`, `test:conc`, `test:usage` (local PostgreSQL; see README).
